# AHTL Exact-Context Guarantee: Review Feedback and Architectural Analysis

## 1. Review Feedback on AHTL Implementation

AHTL’s exact-context claim is strong for **sanitized-byte recovery from CAS**, but it is conditional and should not be extended to mean exact semantic understanding, perfect retrieval, or preservation of pre-redaction input.

### 1.1 Core Assumptions and Where They Can Fail

- **“Exact” begins after sanitization.** The CAS stores `SecretRedactor::sanitize(raw_text)`, not the original input. Delimiter escaping and secret removal are intentionally irreversible. This protects credentials, but it means the system cannot claim bit-exact recovery of the unredacted source payload.
- **The relevant context must be committed and retained.** A `#icx` handle only works if its artifact metadata and every referenced chunk remain available. BLAKE3 detects corruption; it does not restore deleted chunks, lost metadata, unavailable storage, or a handle that was never emitted.
- **Short handles are indexes, not identities.** Profile A uses 48-bit prefixes and Profile B uses 64-bit prefixes. At large artifact counts, prefix collisions become plausible, particularly for 48-bit handles. The design mitigates this by verifying every chunk and the reassembled artifact against a full 256-bit digest, but dereference must reject ambiguity rather than selecting a candidate silently.
- **Cryptographic integrity is not provenance.** Full-digest checks show that recovered bytes match the committed artifact. They do not establish that the original artifact was truthful, safe, correctly attributed, or free from malicious instructions before ingestion.
- **The grammar and implementation must stay synchronized.** Deterministic interpretation depends on identical Unicode handling, canonical lowercase hexadecimal, delimiter escaping, line-ending behavior, byte order, fixed-point conversion, and parser rules. A version mismatch or an alternative implementation that accepts non-canonical syntax can preserve bytes yet assign different structure or meaning.

### 1.2 Compression and Retrieval Are Not Lossless in the Same Sense

- **Skeletons are selective.** AHTL retains signatures, paths, line ranges, diagnostics, and causal operators in the active packet, while eliding bodies, nested config, unchanged diff context, routine logs, and other material into CAS. Therefore, the visible packet is not a complete representation; exact context requires successful dereferencing.
- **HDC, fractal, and Braille fields are routing aids, not reversible artifact encodings.** The 64-bit and 512-bit sketches, 64-bit HDC digest, 16-bit orthant signature, and folded hypervector representations can collide. Their role is candidate filtering and ranking, not proving semantic identity.
- **The IFS suffix result is one-directional.** The specification proves that a shared trailing sequence of projected corner vertices bounds coordinate distance. A small distance alone should not be treated as proof that two original event sequences share an identical suffix: multiple events can map to the same 16-bit majority-projected corner, and fixed-point serialization caps usable depth to about 14–15 steps in Q1.14/Q15 representations.
- **Semantic extraction can be wrong or incomplete.** Domain classification and single-pass skeletonization assume the input is correctly recognized as source, log, diff, or configuration. Minified code, mixed-language files, generated artifacts, malformed logs, unusual diagnostics, and semantically important material inside elided bodies can reduce routing quality even when the CAS copy remains exact.

### 1.3 Security and Operational Pressure Points

- **Redaction coverage is heuristic.** Known token patterns and the entropy gate reduce exposure but can miss secrets in unsupported formats, encoded forms, split values, non-assignment contexts, or low-entropy credentials. Conversely, entropy-based redaction can remove legitimate high-entropy values that matter for diagnosis.
- **Prompt injection is reduced, not eliminated.** Escaping outer delimiters prevents untrusted text from forging an AHTL packet envelope. It does not make the retained source text, diagnostics, identifiers, or CAS-recovered payload non-malicious. Provenance and execution-policy controls remain separate requirements.
- **Retrieval can have false negatives.** Spectral prefilters, Hamming thresholds, surprise-based retention tiers, graph ranking, and top-K limits can fail to surface the needed artifact. A correct artifact in CAS is not equivalent to guaranteed recall into the active context window.
- **Temporal consistency relies on correct graph updates.** Bi-temporal invalidation can suppress superseded facts only when contradictory functional edges are correctly extracted and labeled. Misclassification can leave stale failures active or invalidate a still-relevant fact.
- **Performance claims rely on deployment conditions.** Sub-50 microsecond paging and nanosecond-scale similarity comparisons assume in-memory or local storage, warm caches, the stated CPU capabilities, bounded contention, and healthy `/dev/shm` communication. They are not unconditional end-to-end guarantees.

### 1.4 Minimum Standard for a Defensible Guarantee

Treat “exact context” as valid only when all of these hold:

1. The sanitized artifact is committed before any lossy skeletonization.
2. A full 256-bit digest verifies every returned chunk and the reassembled artifact.
3. Short-handle collisions or ambiguous prefix matches fail closed.
4. Packet parsing and rendering pass exact round-trip tests under a pinned AHTL version and Unicode policy.
5. CAS availability, retention, backup, and access-control guarantees are independently enforced.
6. Retrieval output is distinguished from authoritative recovery: sketches rank candidates, while `deref` or `slice` supplies the authoritative bytes.
7. Test coverage includes corrupted chunks, deleted metadata, prefix collisions, malformed Unicode, parser differentials, redaction bypass attempts, ambiguous line mappings, and retrieval false-negative cases.

**Bottom line:** AHTL can make sanitized stored bytes tamper-evident and exactly recoverable, but its broader context guarantees depend on storage durability, canonical implementations, correct ingestion and extraction, collision-safe handle resolution, and explicit separation of retrieval heuristics from authoritative CAS recovery.

The review feedback in Section 1 is technically sound and aligns with the Master-Core Module 20 (*Exactness Honesty*) mandate: **approximate or heuristic representations must never be conflated with cryptographic byte recovery**.

### 2.2 Point-by-Point Codebase Audit of Core Assumptions (1.1)

#### 2.2.1 Pre-CAS Sanitization Boundary (`SecretRedactor::sanitize`)
- **Review Point:** *"Exact" begins after sanitization. The CAS stores `SecretRedactor::sanitize(raw_text)`, not the original input.*
- **Codebase Reality:** Confirmed by design. In `InfinityContextMmu::ingest_payload_with_exit_code` (`crates/icx-adapters/src/mmu.rs:118-245`), raw input is first bounded to `ICX_MAX_INGEST_BYTES` (`64 MiB`, preferring a newline boundary within the trailing 4,096 bytes so multi-byte scalars and trailing credentials are not split mid-line) and then passed through `SecretRedactor::sanitize(bounded_raw)` (`crates/icx-codec/src/redact.rs:17-52`) **prior** to `self.cas.put_bytes(sanitized.as_bytes())` (`mmu.rs:154`).
- **Explicit Provenance Signaling:** Whenever `SecretRedactor::sanitize` modifies any line of the input (`bounded_raw.lines().ne(sanitized.lines())`), both `InfinityContextMmu::ingest_payload_with_exit_code` (`mmu.rs:145, 163-165`) and `StructuralSkeletonizer::compress_to_packet` (`crates/icx-codec/src/skeleton.rs:27-29`) set bit 7 (`FLAG_IS_REDACTED = 1 << 7 = 0x80`, defined in `crates/icx-codec/src/braille.rs:27`) on byte `B[7]` of `ChannelBHologram`. Furthermore, `SecretRedactor::sanitize` normalizes line endings via `.lines()` + `.join("\n")` (`redact.rs:23, 51`) and replaces `⟪`, `⟫`, `⟦`, `⟧` with `<<`, `>>`, `[[`, `]]` (`escape_ahtl_delimiters`, `redact.rs:55-67`). Consequently, the exactness guarantee is strictly **post-sanitization byte exactness**, and `FLAG_IS_REDACTED` provides an explicit in-band honesty flag whenever pre-CAS scrubbing occurred.

#### 2.2.2 CAS Chunk & Metadata Retention and Fail-Closed Verification
- **Review Point:** *A `#icx` handle only works if its artifact metadata and every referenced chunk remain available. BLAKE3 detects corruption; it does not restore deleted chunks, lost metadata, unavailable storage, or a handle that was never emitted.*
- **Codebase Reality:** Confirmed. `CasStore` (`crates/icx-core/src/cas.rs:54-58`) maintains two `BTreeMap` tables: `chunks: BTreeMap<ArtifactId, (Blake3Digest, Vec<u8>)>` and `artifacts: BTreeMap<ArtifactId, StoredArtifact>`.
  - **Read-Time Verification (`deref_bytes` & `deref_lines`):** `CasStore::deref_bytes` (`cas.rs:202-225`) looks up `StoredArtifact` (returning `Err(IcxError::ArtifactNotFound(id))` if absent), iterates over `meta.chunk_ids`, verifies `Blake3Digest::hash(bytes) == *cdigest` for every `L0` FastCDC chunk (returning `Err(IcxError::IntegrityViolation(cid))` on any single-bit flip), and finally verifies `Blake3Digest::hash(&out) == meta.full_digest` (`cas.rs:220-222`) over the reassembled artifact. `CasStore::deref_lines` (`cas.rs:229-307`) identifies the exact overlapping chunk range `[first_idx..=last_idx]` via `meta.line_index` and verifies the 256-bit `Blake3Digest` of each read chunk (`cas.rs:279-281`).
  - **Persistence & Full Structural Re-Verification (`save_to_dir` / `load_from_dir`):** `CasStore::save_to_dir` (`cas.rs:376-411`) writes `cas_store.json.<pid>.<seq>.tmp` with Unix mode `0o600`, calls `f.sync_all()`, and atomically renames to `cas_store.json`. On reload, `CasStore::load_from_dir` (`cas.rs:414-493`) recomputes `(computed_id, computed_digest) = ArtifactId::hash_bytes(&bytes)` for every stored chunk, rejects duplicate chunk/artifact IDs, recomputes `advance_chunk_line_span` across every `LineIndexEntry` (`cas.rs:454-470`), verifies `computed_bytes == art.total_bytes` and `art.total_lines == expected_total_lines`, and verifies `Blake3Digest::hash(&out) == art.full_digest` before admitting the snapshot.
  - **Operational Scope:** `CasStore` is a single-node content-addressed store, not an erasure-coded or distributed storage engine. If `cas_store.json` is deleted or truncated by an external process, `load_from_dir` and `deref_bytes` fail closed with `IcxError::Io`, `IcxError::ArtifactNotFound`, or `IcxError::IntegrityViolation` (verified by `cas_round_trips_bytes_and_line_slices_and_detects_tampering` and `cas_selective_multi_chunk_deref_lines_and_persistence`, `cas.rs:543-610`).

#### 2.2.3 Short-Handle Birthday Bounds (48-Bit Profile A vs. 64-Bit Profile B) and Ambiguity Rejection
- **Review Point:** *Short handles are indexes, not identities. Profile A uses 48-bit prefixes and Profile B uses 64-bit prefixes. At large artifact counts, prefix collisions become plausible, particularly for 48-bit handles... dereference must reject ambiguity rather than selecting a candidate silently.*
- **Codebase Reality:** Confirmed and enforced across all three resolution layers (`CasStore`, `MerkleContextDag`, and `InfinityContextMmu`):
  - **Birthday-Bound Probability:** For $k$-bit uniform prefixes over $N$ stored artifacts, collision probability is $P_{\text{coll}}(N, k) \approx 1 - \exp\left(-\frac{N(N-1)}{2^{k+1}}\right)$:
    - **48-bit Profile A (`#icx:<12-hex>`, $2^{48} \approx 2.81 \times 10^{14}$):** $P_{\text{coll}} \approx 1.77 \times 10^{-7}$ at $N = 10^4$, $1.77 \times 10^{-5}$ at $N = 10^5$, and reaches $50\%$ at the birthday bound $N_{0.5} \approx 1.18 \times 10^7$ ($\approx 2^{24.5}$).
    - **64-bit Profile B (`#icx:<16-hex>`, $2^{64} \approx 1.84 \times 10^{19}$):** $P_{\text{coll}} \approx 2.71 \times 10^{-10}$ at $N = 10^5$, and reaches $50\%$ at $N_{0.5} \approx 5.06 \times 10^9$ ($\approx 2^{32.2}$).
  - **$O(\log N)$ Range Scan & Fail-Closed Ambiguity Detection:** `ArtifactId::parse_prefix_range` (`crates/icx-core/src/lib.rs:84-105`) maps a 16-hex handle to the exact point range `(Self(val), Self(val))` and a 12-hex handle to the 16-bit inclusive range `(Self(prefix48 << 16), Self((prefix48 << 16) | 0xFFFF))`. Both `CasStore::resolve_handle` (`crates/icx-core/src/cas.rs:97-114`) and `MerkleContextDag::resolve_handle` (`crates/icx-core/src/dag.rs:228-245`) query `BTreeMap::range(min_id..=max_id)` and immediately return `Err(IcxError::AmbiguousHandlePrefix(handle_or_prefix.to_owned()))` if `matches.next().is_some()` after the first match (verified in `cas_trait_context_grep_and_ambiguity_guards`, `cas.rs:652-661`).
  - **Cross-Store Disambiguation:** `InfinityContextMmu::resolve_handle` (`crates/icx-adapters/src/mmu.rs:326-346`) queries both `self.cas.resolve_handle` and `self.dag.resolve_handle`; if both stores match different `ArtifactId` values (`cid != did`), it fails closed with `Err(IcxError::AmbiguousHandlePrefix)`.
  - **Residual Edge Case (Exact 64-Bit `ArtifactId` Collision):** Because `CasStore::put_bytes` (`cas.rs:146-148`) indexes `self.artifacts` by `ArtifactId(u64)` and returns early if `self.artifacts.contains_key(&artifact_id)` without comparing the full 256-bit `full_digest`, a hypothetical 64-bit collision between two distinct payloads ($N \sim 2^{32}$) would deduplicate under the first `ArtifactId`. Phase 5 (`T-52-002`) will harden `CasStore::put_bytes_checked` to verify `existing.full_digest == full_digest` on `ArtifactId` key hits and return `Err(IcxError::AmbiguousHandlePrefix)` if the 256-bit digests differ.

#### 2.2.4 Cryptographic Integrity vs. Provenance and Trust Boundaries
- **Review Point:** *Cryptographic integrity is not provenance. Full-digest checks show that recovered bytes match the committed artifact. They do not establish that the original artifact was truthful, safe, correctly attributed, or free from malicious instructions before ingestion.*
- **Codebase Reality:** Confirmed. `MerkleContextDag` uses domain-separated BLAKE3 Merkle commitments (`b"ICX_DAG_TURN_V1"`, `b"ICX_DAG_TOOL_V1"`, `b"ICX_DAG_BRANCH_V1"`, `b"ICX_DAG_EPOCH_V1"`, and `b"ICX_DAG_EPOCH_FOLD_V1"` in `crates/icx-core/src/dag.rs:40, 345, 434, 604, 679`) verified recursively by `MerkleContextDag::verify_merkle_integrity` (`dag.rs:752-915`). These commitments prove **tamper-evidence after ingestion** and track structural lineage (`AgentKind`, `session_id`, `tool_name`, `exit_code`, `created_at_ms` on `ToolArtifactNode`, `dag.rs:14-35`, and `provenance: ArtifactId` on `BiTemporalEdge`, `crates/icx-store/src/graph.rs:17-29`). However, `AgentKind` and `subject` are caller-supplied parameters to `InfinityContextMmu::ingest_payload_with_exit_code` (`crates/icx-adapters/src/mmu.rs:118-126`), not cryptographically signed attestations from an external hardware root of trust or sandboxed kernel monitor.

#### 2.2.5 Canonical Grammar and Parser Synchronization
- **Review Point:** *The grammar and implementation must stay synchronized. Deterministic interpretation depends on identical Unicode handling, canonical lowercase hexadecimal, delimiter escaping, line-ending behavior, byte order, fixed-point conversion, and parser rules.*
- **Codebase Reality:** Audit of `crates/icx-codec/src/ahtl.rs` and `crates/icx-codec/src/braille.rs` against `docs/ahtl/01-formal-grammar-and-packet-specification.md` and `docs/ahtl/08-v1-reference-implementation-blueprint.md` confirms strong round-trip enforcement (`INV-BRAILLE-01`, `INV-ROUNDTRIP-02`), while surfacing three specific doc-vs-code nuances that must be explicitly documented:
  1. **Bijective Subject Percent-Escaping:** `escape_subject` and `unescape_subject` (`crates/icx-codec/src/ahtl.rs:164-221`) bijectively escape `%` (`%25`), `#L` (`%23L`), `⟦` (`%E2%9F%A6`), `⟧` (`%E2%9F%A7`), `⊢` (`%E2%8A%A2`), `⋮` (`%E2%8B%AE`), and `↦` (`%E2%86%A6`). However, `AhtlClause::render` / `AhtlClause::parse` (`ahtl.rs:114-157`) do not percent-escape clause keys or values; instead, `StructuralSkeletonizer::compact_token` (`crates/icx-codec/src/skeleton.rs:638-658`) replaces reserved delimiters (`⟦`, `⟧`, `⟪`, `⟫`, `⊢`, `⋮`, `↦`, `⇒`, `│`, `\n`, `\r`) with `_` and truncates tokens at 128 UTF-8 bytes.
  2. **Hex Case Normalization on Parse vs. Render:** `AhtlWirePacketV1::parse` (`ahtl.rs:577, 585, 599-600`) and `EpochHeader::parse` (`ahtl.rs:708, 719, 750`) accept any ASCII hex digit (`is_ascii_hexdigit()`) during parsing and normalize to lowercase via `.to_ascii_lowercase()`, so `render()` always emits canonical lowercase hexadecimal (`{:016x}`, `{:012x}`, `{:04x}`).
  3. **Blueprint Struct Field Naming Drift:** `docs/ahtl/08-v1-reference-implementation-blueprint.md` §2.1 illustrates `AhtlWirePacketV1` with illustrative field names (`handle_hex`, `fractal_q15`, `hv_digest`, `spectral_braille_64`, `skeleton`) and `splitn(5, '│')` after stripping `"⟦AHTL v1│"`, whereas the production implementation in `crates/icx-codec/src/ahtl.rs:242-250, 546` uses `cas_handle: ArtifactId`, `compact_48bit_handle: bool`, `slice_hint: Option<String>`, `fractal_coord_hex: String`, `hdc_digest_hex: String`, `braille_spectrum: [u8; 64]`, `skeleton_body: String`, and `splitn(6, '│')` over the full inner payload. Both parse the identical wire string (verified by `profile_a_wire_packet_v1_compact_handles_and_stream_round_trip`, `ahtl.rs:1108-1148`), and `EpochHeader` in `ahtl.rs:668-680` additionally supports `folded=<u32>` (`EpochCountKind::Folded`) for `L4` epochs alongside `τ=<u32>` and `nodes=<u32>`.

### 2.3 Point-by-Point Codebase Audit of Compression & Retrieval Semantics (1.2)

#### 2.3.1 Selective Skeletonization vs. Authoritative `#icx:<hash>` Dereferencing
- **Review Point:** *Skeletons are selective... the visible packet is not a complete representation; exact context requires successful dereferencing.*
- **Codebase Reality:** Confirmed. `StructuralSkeletonizer` (`crates/icx-codec/src/skeleton.rs`) enforces hard clause-count and token-length caps to achieve $15\times\text{--}40\times$ token compression (`INV-SKEL-04`):
  - **Build/Test Logs (`skeletonize_log`, `skeleton.rs:80-197`):** Aggregates passing tests into `✓pass:<count>`, deduplicates all failing test names into `!FAIL@L<line>:<name>`, caps detailed error/panic diagnostic lines (`!ERR@L<line>:<tok>`) at **16 clauses** (`diag_clauses < 16`, `skeleton.rs:160`), and appends `bytes:<len>`.
  - **Unified Diffs (`skeletonize_diff`, `skeleton.rs:199-306`):** Emits `hunks:+<added>/-<removed>`, caps file headers at **4 files** (`seen_files.len() < 4`, `skeleton.rs:228`) and hunk coordinate headers at **4 hunks** (`hunk_count < 4`, `skeleton.rs:250`), and caps extracted symbol/invariant clauses (`⊕sym`, `⊖sym`, `✓pin`) at **16 total clauses** (`clauses.len() < 16`, `skeleton.rs:265, 272, 281`).
  - **Source Code (`skeletonize_source_or_text`, `skeleton.rs:308-429`):** Summarizes header imports (`imports:L<first>-<last>(<count>)`), caps module and symbol declarations (`⊕mod@L<line>`, `⊕L<start>-<end>:<sig>`) at **18 clauses** (`clauses.len() < 18`, `skeleton.rs:359, 371`), caps pinned markers (`PASSKEY`, `INVARIANT`, `SAFETY:`, `TODO:`, `FIXME:`) at **20 clauses** (`clauses.len() < 20`, `skeleton.rs:385`), and limits symbol signature extraction to 56 bytes (`rest.find('{').unwrap_or(rest.len()).min(56)`, `skeleton.rs:509`).
  - **Authoritative Recovery Path:** Every virtualized `AhtlPacket` carries `deref_id: Some(artifact_id)` (`↦#icx:<16-hex>`). When an agent requires the elided body or lines beyond the 16–20 clause cap, it invokes `McpPagerServer::execute_icx_op` (`crates/icx-adapters/src/mcp.rs:113-141`) with `op: "deref"` (`mmu.deref_text(aid)`) or `op: "slice"` (`mmu.deref_lines(aid, start, end)`), or `op: "grep"` (`mmu.grep_cold(target_id, pattern, 25)`).

#### 2.3.2 HDC, Spectral, and Braille Fields as Lossy 1-Lipschitz Routing Filters
- **Review Point:** *HDC, fractal, and Braille fields are routing aids, not reversible artifact encodings. The 64-bit and 512-bit sketches, 64-bit HDC digest, 16-bit orthant signature, and folded hypervector representations can collide.*
- **Codebase Reality:** Confirmed. By the pigeonhole principle, every index projection in `crates/icx-hdc` and `crates/icx-codec` is a many-to-one dimensionality reduction:
  - **`Hypervector::encode_text` ($\Sigma^* \to \{0,1\}^{10240}$, `crates/icx-hdc/src/hv.rs:165-326`):** Splits on non-alphanumeric delimiters (keeping `_`, `:`, `/`), ignores tokens shorter than 2 bytes (`tok.len() < 2`), caps raw token scanning at `MAX_RAW_SCANS = 16_384` and accepted unigram token encoding at `MAX_TEXT_TOKENS = 1024`, and caps per-term reinforcement at `MAX_UNIGRAM_REINFORCEMENTS = 2` and `MAX_BIGRAM_REINFORCEMENTS = 1` using dedicated `2,048`-slot `8`-way linear-probing unigram and bigram tables with tail-slot eviction (`find_reinforce_slot`, `hv.rs:210-233`). Any text beyond the scan horizon is not reflected in the hypervector.
  - **`spectral_bands_64` ($10,240\text{ bits} \to 512\text{ bits}$, `hv.rs:460-481`):** Partitions the 10,240 bits into 512 disjoint 20-bit blocks and sets each output bit if its 20-bit block has Hamming weight $\ge 10$. This satisfies the 1-Lipschitz bound $d_{\text{spectral}}(P, Q) \le d_H(A, B)$ (`splitmix64_seed_and_1_lipschitz_spectral_bands_64`, `hv.rs:820-846`), but discards $95\%$ of the hypervector bits ($20:1$ compression).
  - **`sub_hypervector_64` ($10,240\text{ bits} \to 64\text{ bits}$, `hv.rs:390-398`):** Samples bit 0 of the first 64 `u64` words for Stage-1 pre-screening in `HdcAssociativeIndex` (`160:1` compression).
  - **`hv_digest_u64` and `sketch_u32` (`hv.rs:424-443`):** Linear rotational XOR parity folds (`160:1` and `320:1` reductions). As demonstrated in `delta_rule_bundler_prevents_boilerplate_saturation` (`hv.rs:730-750`), an all-zero vector and an all-ones vector have identical linear XOR parity (`all_zero.hv_digest_u64() == all_ones.hv_digest_u64()`), which is why `HdcBundler` uses the non-linear 128-bit FNV/SplitMix fingerprint `dedup_fingerprint_u128` (`hv.rs:404-420`) for deduplication.

#### 2.3.3 One-Directional IFS Contraction Bound vs. Inverse-IFS Verification and Fixed-Point Horizon
- **Review Point:** *The IFS suffix result is one-directional... multiple events can map to the same 16-bit majority-projected corner, and fixed-point serialization caps usable depth to about 14–15 steps in Q1.14/Q15 representations.*
- **Codebase Reality:** Confirmed, with important nuance in how `icx-hdc` already mitigates geometric boundary false positives:
  - **Many-to-One Corner Vertex Projection (`FractalCoord::corner_vertex`, `crates/icx-hdc/src/fractal.rs:30-41`):** Partitions the 160 words of a `Hypervector` into 16 contiguous blocks of 10 words (`640` bits per block) and thresholds each block at Hamming weight $\ge 320$ to produce a vertex $v(H) \in \{-1.0, +1.0\}^{16}$. Because $2^{10240}$ hypervectors map to $2^{16} = 65,536$ hypercube corners, two distinct events have a $2^{-16} \approx 1.53 \times 10^{-5}$ chance of mapping to the exact same corner vertex by chance (and higher if their text hypervectors are correlated). Thus, `shared_suffix_depth` measures **shared trailing corner-vertex transitions**, not guaranteed event-identity equality.
  - **Boundary-Compatible Inverse-IFS Verification (`FractalCoord::verified_suffix_depth`, `fractal.rs:104-137`):** Simple Chebyshev distance $d_\infty(z_a, z_b) \le 2^{1-K}$ (`shared_suffix_depth`, `fractal.rs:88-98`) is only a one-directional implication: two trajectories in opposite orthants near the origin (e.g., $z_a = [-0.5; 16]$ after one step toward $-1$ vs. $z_b = [+0.5; 16]$ after one step toward $+1$) have $d_\infty = 1.0 \implies L_{\text{shared}} = 1$ despite having opposite transitions. To prevent this false positive, `FractalCoord::verified_suffix_depth` (`fractal.rs:104-137`) explicitly runs the inverse IFS map ($a \leftarrow 2a - 1$ when $a, b \ge 0$; $a \leftarrow 2a + 1$ when $a, b \le 0$) across all 16 dimensions and rejects opposite-orthant endpoints (`pos_one_step.verified_suffix_depth(&neg_one_step) == 0`, verified in `fractal.rs:499-515`). Both `FractalTrajectoryArchive::query_shared_suffix` (`fractal.rs:345`) and `HdcAssociativeIndex::score_entry` (`crates/icx-hdc/src/lib.rs:283`) use `verified_suffix_depth`.
  - **Fixed-Point Serialization Horizon:** In memory, `FractalCoord` stores `coords: [f64; 16]` (53-bit IEEE-754 mantissa), supporting `shared_suffix_depth` up to 32 steps (`fractal.rs:91, 97`). However, when serialized to `Profile A` (`encode_fc_hex64` / `to_q15` with scale $32,767 \approx 2^{15}-1$, `fractal.rs:152-169, 256-280`), `/dev/shm` `SeqlockSlot::fractal_q15_words`, or `to_q1_14` (scale $16,384 = 2^{14}$, `fractal.rs:175-192`), dyadic contractions $2^{-K}$ underflow the least significant bit beyond **$K = 14\text{--}15$ steps**.

#### 2.3.4 Single-Pass Domain Classification and Structural Extraction Limits
- **Review Point:** *Domain classification and single-pass skeletonization assume the input is correctly recognized as source, log, diff, or configuration. Minified code, mixed-language files, generated artifacts, malformed logs, unusual diagnostics, and semantically important material inside elided bodies can reduce routing quality even when the CAS copy remains exact.*
- **Codebase Reality:** Confirmed. `StructuralSkeletonizer::compress_sanitized_to_packet` (`crates/icx-codec/src/skeleton.rs:34-49`) uses a three-branch line-anchored classifier:
  1. `looks_like_test_or_build_log(clean)` (`skeleton.rs:54-72`) checks for 14 line-anchored markers (`running ... tests`, `test result:`, `Compiling `, `error[E`, `thread '... panicked at`, `== ... test session starts`, `Traceback (most recent call last):`, `=== RUN `, `--- FAIL:`, `: error TS`, etc.).
  2. `looks_like_diff(clean)` (`skeleton.rs:75-78`) checks for lines starting with `"diff --git "` or `"@@ -"`.
  3. Everything else falls through to `skeletonize_source_or_text` (`skeleton.rs:308-429`).
- **Known Classification & Extraction Edge Cases:**
  - **Precedence Collision:** If a `git diff` modifies a test runner or snapshot file containing literal lines that start with `error[E` or `Traceback (most recent call last):` (unindented or after diff prefix stripping), `looks_like_test_or_build_log` is evaluated before `looks_like_diff` (`skeleton.rs:42-45`). Because unified diff lines inside hunks are prefixed with `+`, `-`, or ` `, most diff lines do not trigger `starts_with("error[E")`, but `t.contains(": error TS")` (`skeleton.rs:69`) can match inside a TypeScript compiler diff and route the diff to `skeletonize_log`.
  - **Brace Scanner vs. Block Comments & Raw Strings:** `scan_code_braces` (`skeleton.rs:523-567`) tracks `"..."` strings, `'c'` char literals vs. Rust `'a` lifetimes, and `//` line comments, and caps block-end resolution at 500 lines (`take(500)`, `skeleton.rs:622`). It does not track multi-line `/* ... */` block comments, Python `"""..."""` docstrings containing `#`, or Rust raw strings `r#"..."#`.
  - **Minified / Unformatted Files:** If a file has no recognized declaration prefixes (`extract_symbol_signature`, `skeleton.rs:461-518`) and no `PASSKEY`/`INVARIANT`/`TODO` markers, `skeletonize_source_or_text` falls back to emitting a single `head:<first_line_128B>` clause plus `raw_B:<byte_len>` (`skeleton.rs:406-419`). The CAS payload remains 100% intact via `#icx:<hex>`, even though the active stub contains only the file header.

### 2.4 Point-by-Point Codebase Audit of Security & Operational Pressure Points (1.3)

#### 2.4.1 Heuristic and Shannon Entropy Redaction Tradeoffs
- **Review Point:** *Redaction coverage is heuristic. Known token patterns and the entropy gate reduce exposure but can miss secrets in unsupported formats, encoded forms, split values, non-assignment contexts, or low-entropy credentials. Conversely, entropy-based redaction can remove legitimate high-entropy values that matter for diagnosis.*
- **Codebase Reality:** Confirmed by inspecting `SecretRedactor` (`crates/icx-codec/src/redact.rs`):
  - **Potential False Negatives (Missed Secrets):**
    - *Low-Entropy Unassigned Passwords:* A low-entropy password or passphrase appearing outside a recognized key assignment (`is_sensitive_key_name`, `redact.rs:105-133`), CLI flag (`redact_cli_flags`), connection URL (`redact_connection_urls`), or `Bearer`/`Basic` header is not caught by Tier 3 if its length is $< 24$ characters or if it lacks all three of uppercase, lowercase, and digits (`redact.rs:665, 701-706`).
    - *Non-Assignment Hex Secrets:* Under Case A of `is_high_entropy_secret_candidate` (`redact.rs:686-691`), a pure hexadecimal string (`|S| >= 32`, `H(S) > 3.50` bits/char) is redacted **only** if the line contains `=` or `:` (`let is_assignment = full_line.contains('=') || full_line.contains(':');`). A raw 64-hex private key printed alone on a stdout line without `=` or `:` bypasses Case A so that standalone Git commit SHAs in `git rev-list` output are not scrubbed.
    - *Multi-Line Split Tokens:* Because `SecretRedactor::sanitize` processes line-by-line (`for line in escaped.lines()`, `redact.rs:23`) except for stateful `-----BEGIN ... PRIVATE KEY-----` and `-----BEGIN PGP PRIVATE KEY BLOCK-----` envelopes (`redact.rs:20-46`), a credential wrapped across two lines without a vendor prefix on each half can evade token length checks.
  - **Potential False Positives (Over-Redaction of Diagnostic Data):**
    - *High-Entropy Non-Secret Tokens:* Under Case B (`redact.rs:693-707`), any token of length $\ge 24$ drawn from `[A-Za-z0-9+/=-]` containing at least one uppercase letter, one lowercase letter, and one digit with Shannon character entropy $H(S) > 4.35$ bits/char (note: the code threshold in `redact.rs:707` is `4.35`, slightly stricter than the `4.45` cited in early prose) is replaced with `[REDACTED:HIGH_ENTROPY]` unless excluded by path/URL/symbol heuristics (`/` prefix, `./`, `../`, `://`, `\`, `::`, `.`, `(`, `)`, or `#icx:`/`fc:`/`hv:`/`root=` prefixes, `redact.rs:669-684`). Legitimate Base64-encoded crash dumps, serialized protobuf blobs, or long camelCase+digit generated identifiers without dots or colons can therefore be scrubbed to `[REDACTED:HIGH_ENTROPY]`.

#### 2.4.2 Envelope Delimiter Escaping vs. Residual Semantic Prompt Injection
- **Review Point:** *Escaping outer delimiters prevents untrusted text from forging an AHTL packet envelope. It does not make the retained source text, diagnostics, identifiers, or CAS-recovered payload non-malicious.*
- **Codebase Reality:** Confirmed.
  - **Syntactic Envelope Isolation:** `SecretRedactor::escape_ahtl_delimiters` (`crates/icx-codec/src/redact.rs:55-67`) strips `⟪`, `⟫`, `⟦`, `⟧`, and `StructuralSkeletonizer::compact_token` (`crates/icx-codec/src/skeleton.rs:638-658`) additionally strips `⊢`, `⋮`, `↦`, `⇒`, `│`, `\n`, `\r` from every extracted clause token. This guarantees that untrusted tool output cannot break out of a `⟦Ψ:...⟧` stub or inject a forged `⟦Ω:INVARIANT...⟧` packet.
  - **Residual Semantic Injection:** When an LLM calls `icx` with `op: "deref"` or `op: "slice"` (`crates/icx-adapters/src/mcp.rs:113-141`), `McpPagerServer::execute_icx_op` returns the raw (sanitized) text directly inside the JSON-RPC `result.content[0].text` field (`mcp.rs:86-98`). If the underlying file or web response contains adversarial natural-language instructions (e.g., comments instructing the agent to run a destructive shell command), those instructions enter the model's context window verbatim. Defending against semantic prompt injection requires runtime tool-execution policies and human-in-the-loop approval gates in the host agent harness (Master-Core Module 91).

#### 2.4.3 Associative Retrieval False-Negative Surfaces
- **Review Point:** *Retrieval can have false negatives. Spectral prefilters, Hamming thresholds, surprise-based retention tiers, graph ranking, and top-K limits can fail to surface the needed artifact.*
- **Codebase Reality:** Confirmed. Audit of `crates/icx-hdc/src/lib.rs`, `crates/icx-core/src/dag.rs`, `crates/icx-store/src/graph.rs`, and `crates/icx-adapters/src/mmu.rs` identifies five concrete retrieval filtering bottlenecks:
  1. **Stage-1 `candidate_cap` Pre-Screening (`crates/icx-hdc/src/lib.rs:310-380`):** When `self.entries.len() > 64`, `HdcAssociativeIndex::query_associative` computes `candidate_cap = top_k.saturating_mul(4).clamp(16, 64).max(top_k).min(self.entries.len())`. For default `top_k <= 16`, Stage 1 retains at most **64 candidates** using a coarse score (`sim64 * 10 + norm_bloom * 4 + (surprise_q8 >> 1) + quad_sim * 4 + err_flag * 4`) over the 64-bit `sub_hypervector_64()` and 32-bit subject Bloom filter. If an artifact's relevant token appeared in the body rather than the subject and its 64-bit sub-hypervector sample suffers a statistical fluctuation amidst thousands of entries, it can be pruned before Stage-2 10,240-bit SIMD evaluation.
  2. **`Hypervector::encode_text` 1,024-Token Horizon (`crates/icx-hdc/src/hv.rs:165-326`):** Tokens appearing after the first 1,024 non-duplicate tokens of a large artifact are not bundled into the artifact's `Hypervector`. Finding a needle past token 1,024 requires `CasStore::grep_cold` (`op: "grep"`), which scans the full decompressed byte stream (`crates/icx-core/src/cas.rs:337-369`).
  3. **Sealed Epoch Surprise Thresholding (`crates/icx-core/src/dag.rs:10, 550-588`):** When `MerkleContextDag::seal_epoch` seals an `L3` `CacheEpoch`, `format_l3_epoch_body` retains full `L1` AHTL clauses only for turns/artifacts with `surprise >= EPOCH_HIGH_SURPRISE_THRESHOLD` (`0.65`); lower-surprise nodes are compacted into minimal `⟦Ψ:<role>↦#icx:<16-hex>⟧` micro-beacons (`dag.rs:568, 575`).
  4. **PPR Seed Selection in `build_ephemeral_tail_slot` (`crates/icx-adapters/src/mmu.rs:300-315`):** `build_ephemeral_tail_slot` extracts at most **4 whitespace-separated query words** (`filter(|w| w.len() >= 3).take(4)`) to seed `self.graph.personalized_pagerank(&seeds, None, 0.15, 6, top_k)`. If the relevant entity name is the 5th word of the user's prompt or contains punctuation attached to whitespace, it will not seed the PPR walk.
  5. **`SeqlockTelemetryBus` Ring Overwrite (`crates/icx-bus/src/ring.rs:15, 784`):** The shared-memory ring buffer holds `ICX_RING_SLOTS = 256` slots (`3,968` bytes inline AHTL capacity per slot). If a sibling agent publishes $> 256$ events before `requesting_agent` polls, older telepathy frames are overwritten in the ring (though their CAS artifacts remain in `CasStore`), and `build_ephemeral_tail_slot` injects at most **4 sibling telepathy frames** per turn (`sibling_taken < 4`, `mmu.rs:277`).

#### 2.4.4 `BiTemporalGraph` Functional-Edge Supersession Mechanics
- **Review Point:** *Bi-temporal invalidation can suppress superseded facts only when contradictory functional edges are correctly extracted and labeled. Misclassification can leave stale failures active or invalidate a still-relevant fact.*
- **Codebase Reality:** Confirmed.
  - **Allowlist of Functional Relations (`crates/icx-adapters/src/mmu.rs:190-198`):** During `ingest_payload_with_exit_code`, `InfinityContextMmu` iterates over `packet.clauses` and sets `is_functional = matches!(clause.key.as_str(), "status" | "test_status" | "return_type" | "fail" | "pass" | "exit_code")`.
  - **Supersession Scope in `BiTemporalGraph::upsert_edge` (`crates/icx-store/src/graph.rs:294-308`):** When `is_functional` is `true`, `upsert_edge` invalidates any active edge (`e.t_invalid.is_none()`) sharing the exact `(source_entity, relation)` pair by stamping `e.t_invalid = Some(now_ms.max(e.t_valid.saturating_add(1)))` and `e.t_tx_end = Some(now_ms.max(e.t_tx_start.saturating_add(1)))`.
  - **Two Concrete Edge Cases Identified:**
    1. *Line-Numbered Failure Clauses Are Non-Functional:* In `StructuralSkeletonizer::skeletonize_log` (`crates/icx-codec/src/skeleton.rs:144, 165`), individual test failures and compiler errors are emitted with keys `"FAIL@L<line_no>"` and `"ERR@L<line_no>"` alongside summary clauses `"fail"` and `"pass"`. Because `"FAIL@L42"` is not in the `is_functional` allowlist—and because a subsequent passing test run emits `"pass"` (`!fail` is omitted when `fail_count == 0`, `skeleton.rs:177-182`)—an older `"fail"` or `"FAIL@L42"` edge on `subject = "cargo_test"` is **not** automatically invalidated when a later `"cargo_test"` run has `fail_count == 0` unless an explicit `fail: 0` or `status: PASS` functional edge is upserted.
    2. *Subject Granularity:* Because `source_entity` is set to the packet's `subject` (e.g., `"cargo_test"` or a file path `"src/lib.rs"`), upserting a functional relation like `"return_type"` or `"pass"` on a file or suite subject supersedes the previous `"return_type"` or `"pass"` edge for that entire `subject`.

#### 2.4.5 Hardware and OS Assumptions Behind `< 50 us` Paging and `/dev/shm` Seqlock Performance
- **Review Point:** *Sub-50 microsecond paging and nanosecond-scale similarity comparisons assume in-memory or local storage, warm caches, the stated CPU capabilities, bounded contention, and healthy `/dev/shm` communication.*
- **Codebase Reality:** Confirmed. Audit of `crates/icx-bus/src/ring.rs` and `docs/performance.md` reveals an important architectural distinction between the two `SeqlockTelemetryBus` backing modes (`BackingStore`, `ring.rs:244-247`):
  - **`BackingStore::InProcess` (`ring.rs:619-685, 789-845`):** Uses 100% lock-free `AtomicU32`/`AtomicU64` operations (`Ordering::Acquire` / `Ordering::Release` / `Ordering::AcqRel`) over 64-byte cache-line-aligned `FabricHeader` and `SeqlockSlot` arrays on the heap. In this mode, publish/poll latency is genuinely `< 800 ns` (`docs/performance.md` §1) with zero syscalls.
  - **`BackingStore::SharedFile` (`ring.rs:686-747, 846-910`):** To permanently uphold `#![forbid(unsafe_code)]` across all 8 crates (`docs/security-and-threat-model.md` §3) without `unsafe { libc::mmap(...) }`, cross-process `/dev/shm` communication uses positional file I/O (`std::os::unix::fs::FileExt::{read_exact_at, write_all_at}`) and OS-managed advisory file locks (`File::try_lock()` with `50 us` backoff sleep on contention in `with_exclusive_lock`, `ring.rs:204-225`). While backed by a tmpfs RAM disk (`/dev/shm`), each cross-process `publish` performs 4 `pwrite`/`pread` syscalls plus `flock` acquisition, meaning cross-process latency is bounded by Linux VFS syscall overhead ($\sim 2\text{--}15\,\mu\text{s}$ uncontended, and $\ge 50\,\mu\text{s}$ under writer lock contention) rather than raw userspace atomic RAM speed.
  - **Writer Stall Behavior (`MAX_WRITER_SPIN_ITERS = 4096`, `ring.rs:24, 493, 650`):** In `InProcess` mode, if a writer thread crashes or is preempted while holding an odd seqlock version for 4,096 spin iterations, a subsequent writer returns early (`Ok(seq + 1)` in `try_publish`, `ring.rs:650`, or `return` in `set_global_dag_root`, `ring.rs:494`) to avoid deadlock, dropping that slot write rather than blocking indefinitely.

### 2.6 Actionable Roadmap & Specification Refinements (Phases 4–5)

To close every gap identified in this audit before `v1.0.0`, the following concrete engineering items are integrated into the Phase 4 and Phase 5 execution plan:

1. **Full 256-Bit Digest Collision Guard on `CasStore` Insertion (`crates/icx-core/src/cas.rs`, Phase 5 `T-51-001`):**
   - In `CasStore::put_bytes_checked`, when `self.artifacts.get(&artifact_id)` returns an existing `StoredArtifact`, verify `existing.full_digest == full_digest`. If two distinct payloads ever collide on their 64-bit `ArtifactId` prefix, fail closed with `Err(IcxError::AmbiguousHandlePrefix(artifact_id.to_string()))` rather than silently aliasing to the first artifact.
2. **Clear-State Supersession in `InfinityContextMmu` & `BiTemporalGraph` (`crates/icx-adapters/src/mmu.rs`, Phase 4 `T-41-001` / `T-43-001`):**

3. **In-Band Redaction & Exactness Honesty Metadata in `McpPagerServer` (`crates/icx-adapters/src/mcp.rs`, Phase 4 `T-43-001`):**
