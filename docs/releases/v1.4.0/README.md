# icx v1.4.0

Released 2026-11-23. Phase 6, "agent reach and output shrinking":
three new agents, a one-command installer, a read-only MCP tool, and every claim about what icx
does per agent checked against a live run or marked as following the agent's documented contract.
Closes #40 to #44.

## What icx does per agent

The [capability matrix](../../capability-matrix.md) is generated by running each adapter, and CI
fails when it is out of date. In short:

| Agent | Shrinks tool output | Verified |
| --- | --- | --- |
| Claude Code 2.1.330 | yes, for Bash, Read, Grep, Glob, WebSearch, WebFetch, Agent reports and Code Mode | live |
| OpenCode | opt-in (`ICX_OPENCODE_STUB=1`) | live, v2.2.7 |
| Codex CLI 0.171.0, agy 1.5.14, Muse Code 1.4.25 | no: each ignores or refuses replacement, so icx ingests only | live fixtures |
| Hermes v0.23.3 | via the opt-in `icx-terminal` plugin | stand-in tests |
| Gemini CLI, Cursor | opt-in (`ICX_GEMINI_STUB=1`, `ICX_CURSOR_STUB=1`) | documented contract |

Live runs for Hermes, Gemini CLI and Cursor tool calls are deferred to v1.5.0 (#89): the Hermes
gateway stays stopped, Gemini CLI is not installed, and Cursor's usage limit blocked the capture.

## New

- **`icx install --agent <name|all>`** registers icx's hooks and MCP server with each agent. It
  prints every change as a diff, asks before writing (`--dry-run` never writes), backs up each
  file, keeps unknown keys, key order and TOML comments, writes with private modes, follows
  dotfile symlinks, and never duplicates an existing icx hook. `--approve-tools` pre-approves only
  the read-only `icx` tool. Guide §2.11.
- **Gemini CLI and Cursor adapters**, and an **OpenCode plugin** (`integrations/opencode/`).
- **Hermes plugins** (`integrations/hermes/`): the `icx` context engine, with your `compression:`
  settings, per-turn delta ingestion and a non-blocking session start; and `icx-terminal`, which
  stubs large shell results. ICX-AUD-006 is fixed.
- **`icx codex-ingest`** reads Codex rollouts, including `.jsonl.zst`, into the workspace.

## Changed

- **Two MCP tools (ADR-0009).** `icx` is read-only and marked `readOnlyHint`, so Claude Code's plan
  mode and Muse run it without a prompt. `fold` and `xagent` broadcasts move to `icx_write`.
- **Claude Code:** built-in results are stored as their text and stubbed in their own field, only
  for the tool that produced them. Binary data (images) is never replaced. `CwdChanged` moves the
  agent to the new project's workspace without loading the store. `additionalContext` is bounded
  to 8,000 characters and 200 lines.
- **Compaction and session end seal the cache epoch** in Claude Code, Codex, Muse, Gemini
  CLI, Cursor and OpenCode, Hermes seals at `on_pre_compress`, and Claude Code also at a model
  switch. agy fires neither event; its `Stop` seals only on `max_steps_exceeded` or an error.
- **agy:** icx's own MCP replies are no longer ingested when agy loads the tool lazily
  (`call_mcp_tool`); the docs no longer claim injected steps are invisible.

## Upgrading

- **Breaking for MCP callers:** `fold` and `xagent` broadcasts sent to `icx` are refused with an
  error naming `icx_write`. Update instruction files that tell agents to call `fold` on `icx`.
- Reconnect the icx MCP server in each agent after installing; a running server keeps the old
  binary.
- No storage format change. A v1.3.x daemon refuses the new request version, and the hook then
  runs in-process, so mixed versions keep working until the daemon restarts.
- Hermes users: run `icx install --agent hermes`, then set `context.engine: icx` (and optionally
  `plugins.enabled: [icx-terminal]`) in `~/.hermes/config.yaml`.

## Known issues

- The redactor blanks non-secret values after key names containing `token`, `key` or `session`
  (#90). It over-redacts and never leaks; the Phase 7 structural redactor fixes it.
